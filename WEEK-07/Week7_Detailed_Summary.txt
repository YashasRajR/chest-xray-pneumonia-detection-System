During the seventh week of my internship, my entire focus shifted from building new features to actively trying to break what we had already built. At this point in the project, the pneumonia detection website and the hand tracking camera features were fully functional when I used them exactly how they were meant to be used. However, I knew that in the real world, people make mistakes. They click the wrong buttons, upload the wrong files, or sometimes even try to break the system on purpose. My goal for this week was to make the software indestructible, or at least as tough as possible. This phase is what software engineers call destructive testing or adversarial testing.

I started by attacking the file upload system on the medical dashboard. I spent days just uploading the absolute wrong things to our server to see how it would react. For example, I took a normal PDF text document, manually renamed the file so it ended with dot jpg instead of dot pdf, and uploaded it to the server. At first, the server completely crashed. It tried to read a text document as if it were a picture, which confused the deep learning model and caused the entire application to shut down. To fix this, I had to dive deep into the backend code. I rewrote a portion of the upload logic so that the server actually looks inside the file's raw binary data to confirm it is a real image. Now, it ignores the name of the file entirely and only trusts the actual contents. If someone tries to upload a fake image, the server safely rejects it and shows a polite error message on the screen instead of crashing. 

Next, I tested what would happen if I uploaded a massive file. I found a high-resolution image that was twenty megabytes in size and uploaded it. The server struggled to process it, the website froze for almost a minute, and the computer almost ran out of memory. This was a huge red flag because if multiple doctors tried to upload large files at the same time, the entire hospital server could go down. I went back and added strict file size limits on both the webpage itself and the background server. I set the limit to five megabytes, ensuring that anything larger was instantly blocked before it could even reach the deep learning model.

The second half of the week was dedicated to fixing a very frustrating issue with the hand tracking feature. When I tested the camera in a perfectly lit office environment with a plain background, it worked great. But when I took my laptop into a darker room, or sat with a bright window behind me, or even just moved my hand too quickly, the camera started to struggle. The system could still see my hand, but the math calculating the distance between my fingers was jumping around wildly due to the poor image quality. On the screen, the text would rapidly flicker between saying Open Palm and Closed Fist multiple times a second. It was incredibly annoying to look at and made the software feel cheap and broken. 

I realized I could not fix a cheap webcam or control the lighting in someone's room, so I had to fix the problem using software. I spent a lot of time thinking about how to smooth out the results. Eventually, I created a clever workaround using what is called a memory buffer. Instead of having the system guess my hand gesture based on a single, split-second frame of video, I wrote code that forces the system to remember the last ten frames it just saw. Then, it looks at the results from those ten frames and simply picks whichever gesture showed up the most often. For instance, if seven out of the ten frames thought my hand was an Open Palm, but three frames glitched and thought it was a Closed Fist, the screen would confidently display Open Palm and completely ignore the three glitchy frames. This incredibly simple fix completely stopped the screen from flickering. The gesture tracking immediately felt buttery smooth, perfectly stable, and highly reliable. Even when the lighting was terrible or I moved my hand quickly, the text on the screen stayed solid and accurate. It was incredibly satisfying to solve a hardware limitation using just a few lines of clever code.
